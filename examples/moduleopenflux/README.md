# moduleopenflux — модуль OpenFlux (TCP-туннель поверх мессенджеров)

> Порт клиентской половины [OpenFlux](https://github.com/p1neappleXpress/OpenFlux) (GPL-3.0) в
> companion-модуль AntiNet. Контракт модулей — `../../MODULE_API.md`; раскладка зон — `../../README.md`.

Трафик уходит не по своему сетевому протоколу, а **сообщениями внутри мессенджера**: позицией
курсора в документе Яндекс.Документов либо сигнальным каналом звонка MAX. Снаружи это выглядит как
работа в облачном редакторе или звонок, а не как VPN. На той стороне нужен **свой exit-node
OpenFlux** — модуль это только клиент.

```
sing-box → SOCKS5 → gVisor netstack → сырые IPv4-пакеты → транспорт мессенджера → exit-node
```

## Ссылка

```
openflux://yandex?url=<urlencoded адрес документа>[#Имя]                    — апстрим
openflux://oneme?token=<токен MAX>&uid=<id собеседника>[#Имя]                — апстрим
openflux://import?data=<base64url-JSON без паддинга>                        — форк openflux-server
```

Схема ОДНА, транспорт — первый сегмент: `yandex://`/`oneme://` слишком общие имена, чтобы занимать
их в реестре схем хоста. Имена параметров взяты один в один из флагов апстримного CLI
(`-transport`/`-url`/`-maxToken`/`-maxUid`) — своего формата ссылки у апстрима нет вовсе, он
настраивается аргументами командной строки.

Третья форма (`import`) — ссылка, которую выдаёт controlplane форка
[openflux-server](https://github.com/wlruscfd/openflux-server) на созданный ключ (админ-панель /
Android-приложение форка, кнопка «Поделиться профилем»). `data=` — тот же JSON, что и в
`buildDeepLink` форка: `{"name","mode":"key","control_url","key_token","doc_url","transport"}`.
`doc_url`/`transport` читаются прямо из ссылки — модуль НЕ ходит на `control_url` за ними (см.
`decodeImportLink` в `main.go`), ровно как и Android-приложение форка не ходит. `transport: "volga"`
распознаётся, но пока возвращает явную ошибку — сам транспорт (`transport/yandex/volga.go` форка,
~1000 строк) в этот модуль ещё не портирован.

## Раскладка

| Файл / каталог | Зона |
|---|---|
| **`module.json`** | дескриптор: схема `openflux`, `socks5`+`dnsResolver` (каноны), `handoverMode: restart`, `pingTimeoutSec: 60`, три настройки (`dialTimeoutSec`/`keepAliveSec`/`debugLog`) |
| **`native/openflux/cmd/helper/main.go`** | **единственный файл, который принадлежит модулю**: грамматика ссылки, `realMain`, `moduleCall`, SOCKS5-транспорт поверх туннеля, protected-резолвер dial-таргетов |
| `native/openflux/transport/` | апстримные транспорты: `yandex/` (WebSocket + HTTP), `oneme/` (MAX). `oneme/` — только внедрение дозвона (8–17 строк на файл); `yandex/yandex.go` дополнительно несёт фиксы из openflux-server (см. «Что донесено из форка» ниже) + `yandex_test.go` на них |
| `native/openflux/transport/dial.go` | НАШ файл (57 строк): `DialContextFunc`, `NewHTTPClient`, `NewWSDialer` — через них транспорты получают protected-дозвон |
| `native/openflux/tunnel/` | `endpoint.go` (апстрим без правок) + `tunnel.go` (переписан client-only: gVisor-стек, `DialTCP`) |
| `native/openflux/network/`, `utils/` | апстрим без единой правки |
| `dist/` | билды. Gitignored |

**Платформенного кода и build-тегов у модуля нет ни одного.** Точки входа (`shared/entry`),
разговор с хостом (`shared/hostproto`), жизненный цикл (`shared/lifecycle`), protect/off-TUN
(`shared/protect` + `shared/offtun`), SOCKS5 (`shared/socks5`) и резолвер (`shared/dns`) —
каноны, которые `build.py` инжектит перед сборкой и удаляет после.

## Что изменено против апстрима и почему

1. **Дозвон под protect.** Апстрим конструирует `http.Client`/websocket-диалер прямо на месте.
   Под AntiNet так нельзя: UID helper'а ВКЛЮЧЁН в TUN (Husi-pattern), и незащищённый сокет уходит в
   наш же туннель — то есть модуль дозванивается до мессенджера через туннель, который сам же и
   поднимает. Внедрён один параметр `dial transport.DialContextFunc`, всё остальное в транспортах
   не тронуто.
2. **`tunnel.go` переписан client-only.** Апстримный файл нёс обе стороны (клиент и exit-node) и
   поднимал системный TUN. Модулю TUN не нужен и не положен — он отдаёт трафик хосту через SOCKS5,
   поэтому вместо TUN стоит gVisor-netstack (`gonet.DialContextTCP`), а серверная половина убрана.
3. **UDP ASSOCIATE отвечает отказом `0x07`.** Туннель TCP-only по построению, и молчаливое
   «принято» здесь было бы худшим вариантом: sing-box считал бы UDP-каскад поднятым.
4. **Из `max_wclient.go` убран дамп контактов.** Апстрим печатал в stdout имена и телефоны из
   списка контактов аккаунта MAX. В модуле stdout — это `helper.stdout.log`, который читает
   поддержка; персональным данным там не место.

## Что донесено из форка openflux-server и почему

[openflux-server](https://github.com/wlruscfd/openflux-server) — form форка апстрима с рядом
найденных вживую (не в песочнице) багов транспорта Yandex Docs. Ниже — то, что перенесено сюда из
него; апстримная грамматика ссылки и поведение при этом не тронуты (см. «Ссылка» выше).

5. **Свой эхо-пакет через `transport/yandex/yandex.go`.** Документ Яндекса рассылает КАЖДОЕ
   событие `cursor`/`saveChanges` ВСЕМ участникам, включая отправителя — пакет, который транспорт
   только что отправил (`writerLoop`), возвращался по тому же сокету и `handleMessage` скармливал
   его в `CallReceive` неотличимо от настоящих данных пира: собственный исходящий трафик
   реинжектился в собственный туннель. На стороне exit-node форка это проявлялось как паника gVisor
   NAT/forwarding (`unexpected transport protocol = 0`) на совершенно валидных пакетах — паника
   была следствием, а не причиной. `markSent`/`wasRecentlySent` (короткоживущий CRC32 всего
   отправленного) отсекают это без изменения формата провода.
6. **Реальный экспоненциальный backoff при переподключении.** `DefaultConfig()` держал
   `ReconnectDelay: 0`, что делает backoff нерабочим (`0 * что угодно` — всё равно `0`) —
   переподключение било в документ/exit-node без паузы на каждой неудаче. Плюс к этому: если
   сессия держалась дольше 15 секунд перед обрывом (обычный, ничего не значащий обрыв — не признак
   проблемы), следующая попытка теперь считается «свежей», а не продолжает расти от текущего
   счётчика — иначе после нескольких обрывов подряд задержка навсегда залипает на максимуме, даже
   если всё в порядке.
7. **`writerLoop` больше не выкидывает данные из очереди во время обрыва.** `Send()` кладёт пакет в
   очередь, даже когда `IsConnected()` временно `false` (очередь и так переживает переподключение —
   иначе реальному TCP-соединению приходится самому заметить потерю и переотправить по таймауту,
   заметно медленнее). Но `t.session` не обнуляется при обрыве (см. `connectToDoc`), и `writerLoop`
   раньше проверял на `nil` именно `session`/`session.Conn` — эта проверка никогда не срабатывала,
   и данные всё равно вычитывались из очереди и терялись на записи в мёртвое соединение. Теперь
   `writerLoop` ждёт `IsConnected()`, прежде чем вообще трогать канал.
8. **Безопасный разбор `client-config` в `fetchDocInfo`.** Каждое поле было непроверенным
   type assertion (`config["x"].(T)`) — паника при малейшем отклонении формы страницы (страница
   входа, A/B-вёрстка, недогруженный ответ, вьюер-фолбэк из-за другого открытого читателя того же
   документа) валила процесс: паника происходит в горутине без `recover()`. Теперь каждое поле
   проверяется и превращается в обычную ошибку с переподключением.
9. **`openflux://import?data=...`** — см. «Ссылка» выше: совместимость с deep-link'ами, которые
   выдаёт controlplane/приложение форка, без изменения апстримной грамматики.

Транспорт `volga` (собственный транспорт форка, `transport/yandex/volga.go`, ~1000 строк) в этот
модуль **не портирован** — `decodeImportLink` распознаёт `transport: "volga"` в ссылке и явно
отказывает, а не падает и не молча использует не тот транспорт.

## Сборка

```bash
python build.py --os android --module openflux --abis arm64-v8a   # .so (c-shared)
python build.py --os linux   --module openflux                    # desktop
python build.py --os all     --module openflux -y                 # всё сразу
```

`-ldflags=-checklinkname=0` прописан в `module.json` (`build.ldflags`) и подставляется сам.

## Известные ограничения

- **Только TCP.** UDP/QUIC через этот туннель не ходят — значит, UDP-протоколы (hysteria2, tuic,
  wireguard) каскадом за OpenFlux не работают.
- **Нужен свой exit-node.** Публичных нет; ссылка без работающей той стороны подключится «в никуда».
- **Хендовер — `restart`.** Сессия мессенджера привязана к соединению, поднятому на старой сети;
  in-place переустановить её нечем, поэтому при смене сети хост перезапускает helper целиком.
