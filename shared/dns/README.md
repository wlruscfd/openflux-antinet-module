# `shared/dns` — резолв мимо туннеля

Канон из двух половин с разными правилами инжекта. `build.py` копирует их в main-пакет helper'а
перед сборкой и удаляет после — в дереве модуля их нет и быть не должно.

| половина | файлы | гейт |
|---|---|---|
| **прокладка к резолверам** | `dnsshim_*.go` | нет — приезжает всегда |
| **кэширующий резолвер dial-таргетов** | `dns_*.go` | `"dnsResolver": true` |

Гейт build-time-only: его читает только таблица `CANONS` в `build.py`, ни один хост его не
разбирает и в плоский `dist/*/module.json` он не едет.

**Почему прокладка без гейта.** Кэш dial-таргетов — действительно опция: модулю, который резолвит
**внутри** уже поднятого туннеля (qWDTT — через свой netstack), он не нужен, там изоляция от TUN дана
самим туннелем. А вот резолвить **снаружи** туннеля приходится почти каждому — хотя бы чтобы
дозвониться до собственного входа, пока туннеля ещё нет. Держать доступ к резолверам ОС за флагом
«мне нужен кэш» нельзя: это абстракция от платформы, того же класса, что `protect` и `lifecycle`.

## Прокладка

```go
// свои серверы, живым списком
r := protectedNetResolver(transport.BootstrapDNSServers, protectPath)

// резолверы самой ОС
r := systemResolver(protectPath)
```

Отдаёт **стандартный `*net.Resolver`**, а не свой интерфейс: его принимают `net.Dialer.Resolver`,
`http.Transport` и сам `net.DefaultResolver` — переучивать библиотеки, которыми модуль уже
пользуется, не нужно. Протокол DNS ведёт Go, прокладка отвечает только за сокет, поэтому даром
достаются повтор по TCP на усечённом ответе, разбор CNAME и search-домены.

⛔ **`net.DefaultResolver` как он есть — запрещён.** На Android Go берёт cgo-резолвер
(`goosPrefersCgo`, golang/go#10714), а тот не проходит через `net.Dialer`: сокет нечем защитить, и
под VPN запрос уходит в TUN — в туннель, который держится на самом модуле. Резолв ждёт транспорта,
транспорт ждёт резолва.

`PreferGo: true` включает чистый Go-резолвер ради хука `Dial`. Цена — Go читает
`/etc/resolv.conf`, которого на Android нет, и падает на захардкоженный `127.0.0.1:53`. Поэтому
адрес, который просит Go, прокладка отбрасывает и шлёт по своему списку.

**Список — функцией, не срезом.** Резолвер, замкнувший срез, после смены сети продолжит бить в
резолверы прежней сети. Провайдер читается на каждый резолв, поэтому новый список применяется без
пересоздания резолвера. Статический случай — `func() []string { return list }`.

`systemDNSServers()` — резолверы ОС. Три половины под одним именем, поэтому у модуля не появляется
ни одного build-тега:

| платформа | откуда |
|---|---|
| linux, darwin | `/etc/resolv.conf` |
| windows | `GetAdaptersAddresses` **физического** адаптера (Wintun для этого API такой же адаптер, и его DNS ведут внутрь туннеля) |
| android | список, присланный хостом |

**Про android.** Изнутри процесса резолверы системы там взять неоткуда: `resolv.conf` не
существует, netd под VPN резолвит в туннель. Но адреса известны хосту — он читает
`LinkProperties.dnsServers` физической сети, оттуда же их берёт и системный резолвер Android.
Значит присланный список это и есть резолверы ОС, просто путь доставки другой. Забирают его сами
каноны — `parseConfig` и `handleHostEvent` в `shared/hostproto`; модуль не делает ничего.

Пусто → `errNoDNSServers`, а не обход.

## Кэширующий резолвер

```go
r := newProtectedResolver(cfg["DNS_SERVERS"], protectPath)
ips, err := r.LookupHost("example.org")
```

- `DNS_SERVERS=<ip[,ip...]>` — generic ключ конфига (MODULE_API §2.3): физические DNS сети, которые
  хост берёт тем же примитивом, что и для остального клиента. Пусто → прокладка к резолверам ОС;
- TTL-кэш 60с + single-flight: без кэша каждое соединение к тому же хосту платит полный резолв
  заново, без single-flight параллельные дозвоны дублируют запрос (thundering herd);
- A, затем AAAA; по серверам — по очереди, первый успех побеждает;
- сигнатура `LookupHost(string) ([]string, error)` совпадает с интерфейсом `socksResolver` канона
  `shared/socks5` — резолвер отдаётся в `serveSocksUDPAssociate` как есть.

⛔ **Объявил `dnsResolver: true` — объявляй и `dns` в `hostEvents`.** Иначе список приезжает один
раз, при старте, и описывает сеть, активную тогда. После смены сети резолвы уходят в её резолверы
и умирают по таймауту, а транспорт при этом жив — поэтому ни хендовер, ни нудж хоста не помогают.

**Больше от модуля ничего не нужно: обработчика писать не надо.** Резолвер подписывается на список
хоста в своём конструкторе, и каждый новый `dns=` сам доезжает до него и сбрасывает кэш (записи в
нём получены через прежнюю сеть). Пустой список канон не применяет — прежний остаётся.

## Что канон требует от модуля

Прокладке — ничего, кроме `dialControl`, который тоже канон и приезжает безусловно (android-половина
в `shared/protect`, десктопная в `shared/offtun`). Кэширующему резолверу — ещё `golang.org/x/net` в
`go.mod` (пакет `dns/dnsmessage`).

## Тесты

Лежат рядом с каноном и приезжают тем же инжектом; прогон — `build.py --module <mod> --test`.
Разделены по границе гейта: `dnsshim_netresolver_test.go` не трогает `newProtectedResolver`, иначе
модуль без флага не собрал бы тесты вовсе.

## Референс

`examples/moduleecho` — `newProtectedResolver` в `realMain`, `resolver.LookupHost` на CONNECT-пути
и внутри `echoUDPTransport`, разбор `dns=` в обработчике событий хоста.
`examples/moduleopenflux` — прокладка поверх живого bootstrap-списка транспорта.
`examples/moduleqwdtt` — прокладка без кэша: пресет пользователя, затем резолверы ОС.
