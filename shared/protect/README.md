# shared/protect — канонический клиент protect-сервиса AntiNet (инжектируется build.py)

**Единый источник** защиты исходящих сокетов helper'а на **Android**: передача файлового
дескриптора хосту через `SCM_RIGHTS` по UNIX-сокету, хост зовёт `VpnService.protect(fd)`.
Инжектируется **всегда, без гейта в `module.json`** — на Android он нужен каждому модулю.

## Зачем

Helper работает под UID AntiNet, а UID AntiNet **включён** в TUN (Husi-pattern). Значит любой его
исходящий сокет по умолчанию уходит в наш же туннель — то есть модуль дозванивается до своего
сервера через туннель, который сам же и поднимает. `protect(fd)` снимает эту петлю, помечая сокет
как bypass-VPN.

На прочих платформах файл отсекается build-тегом сам: на десктопе ту же роль играет
[`shared/offtun`](../offtun/README.md) (bind к физическому интерфейсу), а `protectPath` там не
используется.

## Почему канон, а не по копии в модуле

Ошибиться здесь легко, а цена ошибки невидима: неудачный protect не даёт ни исключения, ни
ретрая — сокет просто молча уходит в TUN, и модуль дозванивается до своего сервера через туннель,
который сам же и поднимает. Ровно на этом ломались независимые реализации: сравнение `n >= 1`
вместо `n == 1`, чтение ответа поверх буфера отправки и — главное — **проверка только длины ответа
вместо его ack-байта**, из-за чего явный отказ `ProtectFailed` засчитывался как успех.

## Как подключить

Гейта нет — канон приезжает сам, **вместе с адаптером**. Писать `//go:build android`-обёртку не
надо: обе формы protect-хука канонные и называются одинаково на обеих платформах (десктопные тела —
в [`shared/offtun/offtun_adapter.go`](../offtun/README.md)). Модуль просто зовёт нужную:

```go
// форма net.Dialer.Control (echo, qWDTT, OpenFlux)
var pst protectStat
d := net.Dialer{Control: dialControl(protectPath, &pst)}

// форма func(fd int32) bool (masterdns: nativeclient.Options.Protect)
opts.Protect = protectFdFunc(protectPath)
```

`protectPath` приезжает от хоста аргументом/полем конфига (§2.3). Пусто = protect не нужен
(TUN не поднят) — оба конструктора вернут `nil`, и это штатный no-op, а не паника.

## Что даёт канон

| Символ | Что делает |
|---|---|
| `dialControl(protectPath string, st *protectStat) func(network, address string, c syscall.RawConn) error` | адаптер формы `net.Dialer.Control`/`net.ListenConfig.Control`. Парная десктопная половина — в `shared/offtun/` |
| `protectFdFunc(protectPath string) func(int32) bool` | адаптер формы `func(fd int32) bool`. Парная десктопная половина — там же |
| `protectViaService(path string, fd int, st *protectStat) (bool, int)` | сам обмен: SCM_RIGHTS-передача fd на UNIX-сокет хоста + чтение и **проверка ack-байта** (не только длины ответа). Второй возврат — сколько попыток понадобилось: одна против пяти это разница между «сеть тормозит» и «сервис не отвечает» |
| `protectStat` | per-dial замеры: `elapsedMs`, `attempts`, `firstErr` — кладутся в диагностику дозвона, не в глобал. Можно передать `nil` |

Раздельные бюджеты ретрая для двух разных отказов: «обрыв» (`isTransientProtectErr` → немедленный
повтор, плотный backoff до 250 мс) и «сервиса ещё нет» (5 попыток по 60 мс). Смешивать их нельзя —
первый лечится повтором сразу, второй требует подождать подъёма хоста.
